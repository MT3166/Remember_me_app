# 0.3.2 共用 Key 修复

## 复现与修复

旧代码已存在有效图片 Key getter，但只读取文本侧作为共用来源；仅图片侧填 Key 时仍读到空值。另一个可复现路径是只填一个共用 Key 后切换供应商：共用关闭时，原供应商的独立字段和缓存仍为空，随后被判断为未配置图片密钥。

先加入四个回归测试，旧代码四项全部失败；修复后全部通过。

- 文本和图片请求统一通过 `requireKey` 取得有效凭据。共用时，文本 Key 非空则优先，否则使用图片侧已有 Key。
- 两个标签页均可显示、编辑共用 API Key，编辑或清空共用字段会同步两侧，避免残留旧值重新生效。
- 供应商切换时只补齐原供应商缺少的凭据，不将旧 Key 带给新供应商；已有独立 Key 保留。
- 真正缺少共用 Key 时，提示填写共用字段，不误导用户另填一份生图 Key。
- 返回配置页时，未保存修改不再静默丢弃。
- 保持 MiniMax-M3 默认值、数据格式和加密机制，不需要清除旧数据。

- 请求级检查通过：MiniMax / OpenAI 各测试文本侧单 Key、图片侧单 Key；经过真实 Keystore 保存和重载后，执行图片测试与日记封面流程，核验文本、图片请求 URL 和 Authorization 都使用正确凭据。响应通过注入的模拟传输返回，没有调用付费服务。
- UI 回归通过：仅图片侧输入后两页可读；保存并返回；进程重启恢复共用；切换文本供应商保留图片 Key；放弃未保存修改；清空共用 Key 后显示正确错误。
- APK 编译、测试包编译、Lint 和签名校验通过。未新增依赖。
- 界面检查使用测试字符串，完成后恢复了模拟器原配置。
