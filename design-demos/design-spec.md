# 小小日记 UI / UX 重设计

## 目标与已知事实

本项目是给 5 岁女孩使用的安卓日记 APP，目标设备为荣耀平板 V8 Pro。普通话可能不标准，必须先语音转文字，再由可配置的 LLM 给出校准建议，用户确认后生成图片封面。已有 Kotlin Compose 0.1.0 APK，支持本机草稿、文字编辑、原文对照、系统语音识别与朗读、OpenAI / Anthropic 文字协议和 MiniMax 生图。现有实现与验证记录以 README.md、docs/verification.md 为准。本次不假定真机语音已经验证，也不宣称真实模型结果已取得。

## 使用者与场景

主要使用者年龄小，阅读和抽象概念理解能力尚在发展，界面不能依赖密集标签与表单。孩子通常拿着平板竖屏说话，家长偶尔协助文字确认和模型设置。日记不应变成作业，不设置打卡压力、排名或连续天数。开心、平静与难过的内容都应被接纳。目标是孩子自己能找到开始录音、结束录音、听一遍和保存这些关键动作；需要检查语义时，家长能够快速进入文字与原文对照。

## 核心流程与内容

每个方向均展示四个主要状态：日记首页、记录、确认、阅读。首页展示同一批明确为演示的日记，日期与标题相同，便于比较。录音采用点按开始、点按结束，避免持续按住造成疲劳。录音完成后再进入确认，不在一个屏幕同时塞入原文、校准结果和封面操作。确认提供朗读、文字修改与原文查看；保存后进入阅读状态，封面可重新生成或暂时跳过。生图失败不阻止正文保存。家长设置独立，按实际功能保留协议、地址、模型与密钥的职责边界。

演示短文：今天我和妈妈去了公园。我画了一个大太阳，我好开心！其他封面示例围绕绘画、公园与早餐，均为原型内容，不冒充孩子的真实经历。

## 格式与尺寸

交付三个可直接打开的独立 HTML，每个 HTML 默认平铺四个主要屏幕，并提供单屏实际体验入口。每台预览均可单独交互。单屏模式按 800x1280 平板竖屏、1280x800 平板横屏、390x844 窄屏验证，不仿造 iPhone 刘海或将安卓设备包装成 iOS。平铺用容器查询适配缩略设备，单屏保持真实触控目标；不按视口比例缩小字号。主要动作触控区域至少 56px，正文 18px 左右，辅助文字不小于 12px。重要动作固定在内容区之后的底部栏，滚动内容单独留空间，键盘与安全区不覆盖按钮。

## 设计假设与边界

用户写的 huash-desgin 对应已安装的 huashu-design。尚未收到新的品牌规范，暂沿用小小日记名称与图书标识的语义。三个方向采用不同的导航或构图，不只更换颜色。颜色来自日记主题的纸张、叶子、绘画颜料和晴天，使用多个有区别的色相；避免全粉色、公主刻板印象、深蓝 SaaS 仪表盘、紫色渐变与满屏装饰卡片。展示用图片是实际下载、带来源的原型封面素材，不是用户日记照片或本项目模型生成的结果。没有内置生图工具时不私自切换付费生图 API。

## 三个独立推导入口

A：秒数轮盘 17，Functional Brutalism。借用清楚的网格与日期层级，去除不适合幼儿的小字和高密度，形成亮色故事画廊。结构为大图日记墙、底部录音入口、安静的全屏记录。

B：现实参照，Khan Academy Kids 的儿童操作入口与清晰反馈，使用官方页面核实，不复制其角色或标志。结构为单一醒目的语音操作区、明确步骤、确认前先听。

C：设计思维参照，IDEO 以使用者行为和原型反馈推动交互的工作方式。以亲子翻阅为种子，采用书页式内容、清晰页边导航、正文与封面在横屏组成阅读跨页。

## 验证与选择

三版均验证首页进入详情、录音状态切换、确认与返回、原文展开、窄屏与横屏无溢出、图片加载、控制台无错误。原型用示例输入演示，不实际调用麦克风、模型或保存真实日记。三版截图与交互完成后，请用户根据可见结果选择；选择前不更改安卓生产界面，不写不存在的方向批准记录。
